§Suriname terms used here ↑ top

TermMeaning
BTWBelasting over de Toegevoegde Waarde — Suriname VAT (currently 10%). Configurable per product; basic foods & medicine can be BTW-exempt.
BelastingdienstSuriname Tax Authority — receives BTW filings. Represented in Josbin by the Tax Inspector role.
RekenkamerCourt of Audit — for government accountability. Josbin produces a signed, tamper-evident audit export for it.
WBP-SWet Bescherming Persoonsgegevens Suriname — the personal-data protection law. Drives PII encryption + the customer "right to erasure".
SRDSurinamese Dollar — all money is stored as exact decimals (never floating point).
ASTAmerica/Paramaribo time (UTC−3) — every timestamp and every report day-boundary uses it.
Z-ReportEnd-of-day register close (cash reconciliation + day totals). X-Report is a mid-day snapshot that does not close the register.

Exchange rate is never missing

The day's rate self-heals in order: already locked → fetch from the rate API → carry forward yesterday's → a configured static fallback. The locked rate is stamped on every sale for audit.

Stock can't silently oversell

Stock is reduced inside the same transaction as the sale (never a flaky background job). Default policy allows honest negative stock to surface bad counts; a store can switch to strict "block oversell".

Profit captured at sale time

Cost and profit are snapshotted onto each line as it sells, so profit reports stay correct even if the product's cost changes later.

8c · Who does what, in order

sequenceDiagram autonumber actor OA as Org Admin participant SYS as Josbin server actor TI as Tax Inspector (Belastingdienst) OA->>SYS: Generate BTW filing for period SYS->>SYS: Aggregate sale items (AST window),
split taxable vs exempt SYS->>SYS: Hash-chain the filing to the org's last one OA->>SYS: Submit to Belastingdienst SYS-->>TI: Filing appears (cross-org, read-only, 2FA) TI->>SYS: Review figures + source breakdown alt Figures correct TI->>SYS: Accept SYS-->>OA: Marked Accepted (filed) else Problem found TI->>SYS: Dispute + note SYS-->>OA: Marked Disputed OA->>SYS: Correct & supersede (refile) SYS-->>TI: New filing (links to original) end
Why the hash chain matters. Each filing carries a SHA-256 fingerprint of itself plus the previous filing's fingerprint, per organisation. Change any historical figure and the chain breaks — so the Belastingdienst and Rekenkamer can trust the record hasn't been altered after the fact. Day boundaries use AST, so a 23:30 sale counts on the correct day, not the next one.

9The compliance backbone (always on) ↑ top

These protections run underneath every flow above — they are not a separate screen, they are how the system behaves on every write.

Immutable audit trail

Every action is hash-chained and append-only. No user can edit or delete a row without breaking the chain.

PII encryption (WBP-S)

Customer personal data is encrypted field-by-field. A customer can be erased on request while sales history stays intact.

Code & licence protection

PHP is IonCube-encoded, the desktop app is code-signed, and a licence (hardware-bound) is checked on start and every 24h.
